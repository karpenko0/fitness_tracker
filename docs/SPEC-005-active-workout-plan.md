# SPEC-005: План разработки активной силовой тренировки

## Объём MVP

Реализовать активную тренировку в Nest API и Telegram Mini App на базе уже существующих `Workout`, `WorkoutExercise` и `WorkoutSet`. Существующие запланированные тренировки остаются совместимыми: статус `PLANNED` используется как черновик для ранее созданных записей, а новый `DRAFT` используется для явного создания тренировки.

## Этапы

1. Расширить Prisma-схему и миграцию: источники и состояния тренировки, снимки плановых и фактических подходов, REST-таймер, аудит и индексы.
2. Реализовать API активной тренировки: создание ручной тренировки, чтение, запуск, изменение/добавление/пропуск подходов, управление отдыхом и завершение.
3. Реализовать инварианты сервиса: ownership, доступность пользователя, переходы статусов, optimistic locking, идемпотентность, расчёт объёма и инвалидирование dashboard snapshot.
4. Реализовать экран `/workouts/:workoutId`: загрузка, ввод фактических данных, отложенное автосохранение, статусы синхронизации, офлайн-очередь и REST-таймер по абсолютному `endsAt`.
5. Покрыть чистые расчёты и критичные сценарии unit-тестами, выполнить генерацию Prisma-клиента, сборку backend и frontend, затем тесты.

## Ограничения текущего репозитория

В текущей схеме отсутствуют каталог упражнений, программы с составом упражнений и шаблоны. Поэтому источник `MANUAL` реализуется полностью, а источники `PROGRAM`/`TEMPLATE` возвращают явную ошибку в MVP до появления соответствующих справочников. Контракты и модель данных расширены так, чтобы подключить снимки этих источников без переработки активной тренировки.
