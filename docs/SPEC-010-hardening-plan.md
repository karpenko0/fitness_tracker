| # | Задача | Почему | Критерий готовности |
|---|---|---|---|
| 1 | Роли `USER/TRAINER/ADMIN/SUPER_ADMIN` — идемпотентной миграцией | без `seed.ts` первый вход падает (P2025) | вход на чистой БД после одних миграций |
| 2 | Чистая сборка: 50 ошибок `tsc` в модулях прогресса/замеров | `nest build` не проходит; часть ошибок — реальные баги | `tsc --noEmit` = 0 ошибок |

| 2d | Маршруты замеров/фото/графиков вне `/api/v1` | нарушение общего контракта API | `/api/v1/measurement`, `/api/v1/progress-photo`, `/api/v1/progress-chart`, `/api/v1/progress-comparison` |

Попутно найдено и исправлено в модулях прогресса: недельная/месячная группировка графика теряла все точки,
кроме последней (неверная проверка ключа в `Map`); граница предыдущего периода сравнения была `NaN`
(`getMilliseconds` без вызова); DAY-график отдавал `localDate` вместо `date`; Decimal-значения агрегатов
складывались как объекты; объём по мышцам запрашивал несуществующую связь `exercise`; `PrismaModule` поднимал
движок Prisma при импорте (нестабильные падения тестов) — теперь фабрика + `$disconnect` при остановке.

Известное ограничение (вне SPEC-010): агрегаты замеров пересчитываются только по событию завершения тренировки,
поэтому новый замер появляется на графике веса после следующей завершённой тренировки.
